Federation PPV Stream

PPV Stream bisa bergabung dengan instance PPV Stream lain lewat ActivityPub. Instance saling bertukar katalog video (judul, harga, link checkout), bukan file video. Pembayaran dan streaming selalu terjadi di server asal video.

Ringkasan

Apakah federation bekerja sempurna?

Sebelum auditTidak

Ada 11 masalah, termasuk tanda tangan yang bisa dipakai ulang, actor yang bisa menghapus video milik instance lain, endpoint admin tanpa autentikasi, dan follow keluar yang tidak pernah bisa diterima.

Sesudah perbaikanLayak uji

Kesebelas masalah sudah diperbaiki di kode dan ditambah unit test. Alur follow, publish, update, dan delete antar instance seharusnya berjalan.

Belum sempurna6 catatan

Enkripsi kunci privat belum AEAD, belum mendukung authorized fetch, bagi hasil lintas instance belum tersambung ke pembayaran, dan belum ada UI admin.

Sudah diuji?Sebagian

Unit test ditulis. Uji integrasi dua instance (tests/federation_integration.sh) butuh Docker dan belum dijalankan di sesi ini.

Konsep

Model index-only

Setiap instance hanya mengumumkan metadata video publik. Instance lain menyimpannya di tabel remote_video_catalog dan menampilkannya di katalog. Saat penonton ingin membeli, mereka diarahkan ke checkout_url di server asal.

Pengiriman keluar memakai antrean federation_delivery_jobs. Gagal kirim dicoba lagi dengan jeda 2n detik (maksimal 1 jam), hingga 10 kali.

Keamanan inbox

Pemeriksaan setiap activity masuk

  1. Domain pengirim dicek terhadap aturan moderasi (federation_domain_rules); domain yang diblokir ditolak.
  2. Header Digest wajib ada dan harus cocok dengan SHA-256 body.
  3. Header Signature wajib menandatangani (request-target) host date digest. Header Date harus berada dalam 300 detik dari waktu server.
  4. Dokumen actor diambil lewat HTTPS dengan proteksi SSRF (tanpa IP privat, maksimal 128 KB, timeout 10 detik).
  5. keyId tanda tangan harus milik actor tersebut, dan id activity harus satu origin dengan actor.
  6. Tanda tangan RSA-SHA256 diverifikasi. activity_uri unik di database sehingga activity yang sama tidak diproses dua kali.
  7. Untuk video: id, URL kanonik, dan URL checkout harus satu origin dengan actor. Delete hanya menghapus entri milik actor pengirim.

Keamanan dan data pribadi

  • Data yang dipublikasikan: username kreator dan metadata video publik dikirim ke server lain dan tidak bisa ditarik sepenuhnya (server remote bisa menyimpan salinan). Beri tahu kreator sebelum mengaktifkan federation, dan minta persetujuan per video (UU PDP: dasar pemrosesan dan transfer data).
  • Penghapusan: Delete dikirim saat video dijadikan local_only, tetapi kepatuhan server lain tidak bisa dijamin.
  • Kunci kriptografi: lihat keterbatasan enkripsi kunci (A.8.24). Simpan HMAC_SECRET dan FEDERATION_ADMIN_TOKEN hanya di secret Dokploy (A.5.17).
  • Log: federation_activities menyimpan payload activity masuk dan keluar. Tetapkan masa simpan (A.8.10) dan batasi akses admin (A.8.15).
  • Moderasi: gunakan domain rules untuk memblokir instance bermasalah (A.5.14 transfer informasi).
Belum sepenuhnya patuh.Enkripsi kunci privat belum memakai algoritma terautentikasi, belum ada mekanisme persetujuan kreator per video, dan belum ada kebijakan retensi log federation. Selesaikan sebelum federation diaktifkan di produksi.
