Setup PPV Stream

Langkah dari nol sampai siap dipakai: menjalankan aplikasi di laptop, deploy ke Dokploy, membuat admin, mengaktifkan gateway pembayaran, dan men-deploy smart contract x402 di Polygon. Setiap variabel X402_* dijelaskan beserta cara mendapatkannya.

Prasyarat

Lokal dengan Docker

  • Docker Desktop / Engine + Compose v2
  • make

Lokal tanpa Docker

  • Rust stable (≥ 1.91)
  • PostgreSQL 16 + psql
  • FFmpeg

Kontrak x402

  • Node.js 18+ dan npm
  • MetaMask di browser
  • Akun penyedia RPC (Alchemy / Infura / QuickNode), opsional
rustc --version && cargo --version && psql --version && ffmpeg -version && node --version
Langkah 1

Menjalankan di komputer lokal

Dengan Docker (disarankan)

cp .env.example .env      # isi HMAC_SECRET, ADMIN_BOOTSTRAP_*
make db-up
make wait-db
make migrate
make build
make run-all
make seed                 # opsional: pengguna dummy

Tanpa Docker

export DATABASE_URL=postgres://ppv:pass@localhost:5432/ppv_stream
mkdir -p storage media hls_tmp tmp
for f in sql/*.sql;        do psql "$DATABASE_URL" -f "$f"; done
for f in migrations/*.sql; do psql "$DATABASE_URL" -f "$f"; done
cargo build
cargo run

Buka http://localhost:8080. Build Rust membutuhkan database aktif karena makro sqlx::query! memeriksa SQL saat kompilasi. Jika build gagal dengan pesan error communicating with database, jalankan database dan migrasi terlebih dahulu.

Migrasi di migrations/ juga dijalankan otomatis saat aplikasi start (dicatat di tabel _ppv_extra_migrations). Matikan dengan APPLY_EXTRA_MIGRATIONS=0.

Langkah 2

Deploy ke Dokploy

  1. Di Dokploy, buat Project → Compose, hubungkan repo Git, dan isi Compose Path docker-compose.dokploy.yml.
  2. Buka tab Environment, salin isi .env.dokploy.example, lalu ganti semua CHANGE_ME. Buat secret dengan openssl rand -hex 32.
  3. Tab Domains: tambahkan domain ke service app, port 8080, aktifkan HTTPS (Let's Encrypt). Jangan buka port database ke publik.
  4. Klik Deploy. Dockerfile menjalankan Postgres sementara di tahap build agar makro sqlx bisa memeriksa SQL, lalu image runtime hanya berisi binary, FFmpeg, dan tini.
  5. Cek https://domain/health atau log service. Data tersimpan di volume pgdata dan appdata (/data).

Detail backup, alternatif Dokploy Postgres, dan troubleshooting ada di DOKPLOY.md.

Langkah 3

Membuat admin pertama

  1. Isi ADMIN_BOOTSTRAP_TOKEN, ADMIN_BOOTSTRAP_EMAIL, dan ADMIN_BOOTSTRAP_PASSWORD (kuat, bukan default ChangeMe123!).
  2. Buka https://domain/setup_admin?token=TOKEN. Endpoint ini mati sendiri setelah ada satu admin.
  3. Hapus ADMIN_BOOTSTRAP_TOKEN dan ADMIN_BOOTSTRAP_PASSWORD dari env, lalu deploy ulang.
  4. Masuk di /public/admin/login.html, ganti password, lalu buka Settings untuk branding, SMTP, storage, dan metode pembayaran.

Langkah 5

Gateway pembayaran fiat

Aktifkan provider di PAYMENT_PLUGINS (misalnya paypal,xendit,midtrans,stripe), isi kuncinya, lalu daftarkan URL webhook di dashboard provider. Pakai mode sandbox/test dulu.

ProviderAmbil kunci diEnvURL webhook
MidtransDashboard Midtrans → Settings → Access KeysMIDTRANS_ENV, MIDTRANS_SERVER_KEY, MIDTRANS_CLIENT_KEY/api/pay/midtrans/webhook (Payment Notification URL)
XenditDashboard Xendit → Settings → API Keys; Webhooks → verification tokenXENDIT_ENV, XENDIT_SECRET_KEY, XENDIT_WEBHOOK_TOKEN/api/pay/xendit/webhook (Invoice paid)
StripeDashboard Stripe → Developers → API keys; Webhooks → signing secretSTRIPE_ENV, STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET/api/pay/stripe/webhook (checkout.session.completed)
PayPaldeveloper.paypal.com → Apps & Credentials; buat webhook untuk mendapatkan IDPAYPAL_ENV, PAYPAL_CLIENT_ID, PAYPAL_CLIENT_SECRET, PAYPAL_WEBHOOK_ID/api/pay/paypal/webhook (CHECKOUT.ORDER.APPROVED, PAYMENT.CAPTURE.COMPLETED)

URL webhook ditulis lengkap dengan domain, misalnya https://stream.example.com/api/pay/xendit/webhook. Midtrans dan Xendit menagih dalam rupiah. Server memeriksa nominal dan mata uang webhook sebelum membuka akses.

Langkah 6

Wallet internal dan deposit

  1. Admin > Settings > Payment Methods: aktifkan pembayaran wallet dan, jika perlu, transfer antar pengguna.
  2. Isi WALLET_DEPOSIT_INSTRUCTIONS dengan rekening tujuan, misalnya:
    Bank: BCA\nNo. Rekening: 1234567890\na.n. PT Contoh\nCantumkan username di berita transfer.
  3. Pengguna mengunggah bukti; admin memeriksa di Admin > Wallet > Deposits sebelum menekan Approve.
Regulasi.Saldo yang bisa ditransfer dan ditarik dapat dikategorikan uang elektronik yang memerlukan izin Bank Indonesia. Kaji sebelum mengaktifkan transfer dan penarikan untuk publik.
Langkah 7

Kurs rupiah dan oracle harga token

Job latar mengambil USD/IDR (default dari open.er-api.com, tiap jam) dan harga token native seperti POL (dari CoinGecko, tiap 2 menit, hanya untuk token aktif yang bukan stablecoin). Kurs dipakai untuk tagihan Midtrans/Xendit, harga video dalam rupiah, dan invoice x402 token native.

EnvDefaultFungsi

Override manual: Admin > Settings > Exchange Rates & Token Prices. Setiap perubahan tercatat di fx_rate_history. Container harus bisa mengakses internet keluar (HTTPS) untuk refresh otomatis.

Langkah 8

Setup kontrak x402

Kontrak contracts/contracts/X402Splitter.sol menerima pembayaran, membagi dana ke kreator dan admin dalam satu transaksi, lalu memancarkan event Paid. Server menandatangani setiap invoice dengan kunci admin; kontrak menolak tanda tangan lain, invoice kedaluwarsa, invoice yang dipakai dua kali, dan pembayaran kurang.

sequenceDiagram
  participant P as Pembeli (MetaMask)
  participant S as Server PPV
  participant K as X402Splitter
  P->>S: POST /api/pay/x402/start
  S->>S: hitung jumlah token, tanda tangani (X402_ADMIN_PRIVKEY)
  S-->>P: invoice + v, r, s + deadline
  P->>K: payNativeSigned / payERC20Signed
  K->>K: cek tanda tangan admin, deadline, invoice belum dipakai
  K-->>P: dana → kreator (90%) dan admin (10%), emit Paid
  P->>S: POST /api/pay/x402/confirm (tx_hash)
  S->>S: baca receipt via X402_RPC_HTTP, cocokkan event → buka akses
Penting: alamat admin berperan ganda.Alamat yang dimasukkan ke konstruktor kontrak (X402_ADMIN_WALLET) adalah penandatangan invoice sekaligus penerima bagian platform. Kuncinya disimpan di server, jadi wallet ini termasuk hot wallet. Pindahkan pendapatan secara rutin ke wallet dingin atau multisig. Alamat admin tidak bisa diubah (immutable), sehingga mengganti kunci berarti men-deploy kontrak baru.

Membuat wallet admin baru

Jalankan di komputer yang aman (bukan di server produksi), setelah npm install di folder contracts:

cd contracts
npm install
node -e "const {Wallet}=require('ethers'); const w=Wallet.createRandom(); console.log('X402_ADMIN_WALLET=' + w.address); console.log('X402_ADMIN_PRIVKEY=' + w.privateKey)"

Alternatif: di MetaMask buat akun baru → Account details → Show private key. Cara ini lebih mudah, tetapi kunci tersimpan juga di browser.

Jangan menempelkan kunci privat ke chat, tiket, atau commit Git. Bersihkan riwayat terminal setelah menjalankan perintah di atas.

Wallet deployer

Deploy membutuhkan wallet berisi sedikit POL untuk gas. Wallet deployer boleh sama dengan wallet admin, tetapi lebih aman dipisah. Isi saldo testnet dari faucet resmi Polygon (faucet.polygon.technology) atau faucet milik Alchemy/QuickNode.

Langkah 8b

Deploy kontrak dengan Hardhat

  1. Buat file contracts/.env (sudah di-ignore, jangan di-commit): 
    PRIVATE_KEY=0xKUNCI_WALLET_DEPLOYER
ADMIN_WALLET=0xALAMAT_X402_ADMIN_WALLET
AMOY_RPC_HTTP=https://polygon-amoy.g.alchemy.com/v2/API_KEY
AMOY_CHAIN_ID=80002
POLYGONSCAN_API_KEY=            # opsional, untuk verifikasi source
AUTO_VERIFY=true                # opsional
CONFIRMATIONS=2
  2. Kompilasi dan perkirakan biaya: 
    npx hardhat compile
npm run estimate:test
  3. Deploy ke Amoy: 
    npm run deploy:test
# setara: npx hardhat run --network polygonAmoyTestnet scripts/deploy_x402.js
    Output mencetak Address dan link explorer. Alamat yang sama tersimpan di contracts/deployed.json.
  4. Buka alamat di amoy.polygonscan.com dan pastikan fungsi baca admin() mengembalikan X402_ADMIN_WALLET.
  5. Isi env aplikasi: X402_CONTRACT_ADDRESS, X402_ADMIN_WALLET, X402_ADMIN_PRIVKEY, X402_RPC_HTTP, X402_CHAIN_ID=80002. Deploy ulang aplikasi.
  6. Aktifkan x402 di Admin > Settings > Payment Methods.

Script deploy:test sebelumnya menunjuk jaringan megaTestnet yang tidak ada di hardhat.config.js; sudah diperbaiki menjadi polygonAmoyTestnet.

Langkah 8c

Token pembayaran

Token yang ditawarkan ke pembeli diambil dari tabel pay_tokens. Migrasi sudah mengisi POL native di Amoy (80002) dan USDC.e di Polygon (137).

JenisCara dihargaiSyarat tampil
Stablecoin (USDC, USDC.e, USDT, DAI, atau token_kind='STABLE')1 token = 1 USDSelalu
Token native / volatil (POL, ETH)Harga oracle CoinGecko, dibulatkan ke atasAda harga segar (≤ 10 menit) atau override admin
Token tanpa harga1:1 (hanya testnet)X402_ALLOW_VOLATILE_TOKENS=1

Contoh menambahkan USDC uji di Amoy (ambil alamat kontrak USDC Amoy dari dokumentasi Circle, lalu verifikasi di explorer):

INSERT INTO pay_tokens (symbol, chain, chain_id, erc20_address, decimals, is_active, token_kind)
VALUES ('USDC', 'Polygon Amoy Testnet', 80002, '0xALAMAT_USDC_AMOY', 6, TRUE, 'STABLE')
ON CONFLICT ON CONSTRAINT pay_tokens_chain_symbol_uq DO UPDATE
SET erc20_address = EXCLUDED.erc20_address, decimals = 6, is_active = TRUE, token_kind = 'STABLE';

Di mainnet, USDC yang di-seed (0x2791…4174) adalah USDC.e hasil bridge. Jika ingin USDC native Circle, tambahkan baris terpisah dengan alamat resminya.

Langkah 8d

Watcher (opsional)

Biasanya halaman watch langsung mengonfirmasi pembayaran setelah transaksi masuk blok. Watcher adalah cadangan untuk kasus pembeli menutup browser sebelum konfirmasi.

  1. Build image dengan fitur watcher: set ENABLE_WATCHER=1 (build arg) di Dokploy.
  2. Isi X402_RPC_WSS dan X402_CONTRACT_ADDRESS, lalu set WATCHER_ENABLE=1 (runtime).
  3. Untuk menjalankannya sebagai service terpisah, tambahkan COMPOSE_PROFILES=watcher.
Langkah 8e

Menguji pembayaran di testnet

  1. Di MetaMask, tambahkan jaringan Polygon Amoy (chain ID 80002) lewat chainlist.org, lalu isi POL uji dari faucet.
  2. Login sebagai kreator, isi EVM Wallet di profil, lalu upload video berbayar.
  3. Login sebagai pembeli (akun lain), buka video → tab Blockchain x402 → Connect Wallet → Pay with Crypto Wallet.
  4. Setujui di MetaMask. Setelah terkonfirmasi, halaman memuat ulang dan video terbuka.
  5. Periksa transaksi di amoy.polygonscan.com: ada dua transfer (kreator dan admin) dan event Paid.
Langkah 8f

Pindah ke mainnet

  1. Isi POLYGON_RPC_HTTP dan POLYGON_CHAIN_ID=137 di contracts/.env, isi wallet deployer dengan POL asli, lalu jalankan npm run deploy:mainnet.
  2. Ganti env aplikasi: alamat kontrak mainnet, RPC mainnet, X402_CHAIN_ID=137.
  3. Nonaktifkan token testnet: UPDATE pay_tokens SET is_active = FALSE WHERE chain_id = 80002;
  4. Pastikan X402_ALLOW_VOLATILE_TOKENS=0.
  5. Lakukan kajian hukum dahulu. Di Indonesia, aset kripto bukan alat pembayaran yang sah.
Langkah 9

Federation (opsional)

Isi FEDERATION_ENABLED=true, FEDERATION_BASE_URL, FEDERATION_DOMAIN, dan FEDERATION_ADMIN_TOKEN. Penjelasan lengkap, status, dan batasannya ada di federation.html.

Checklist go-live

  • Semua CHANGE_ME sudah diganti; .env tidak ada di Git.
  • HTTPS aktif; SESSION_COOKIE_SECURE=true; ENABLE_STATIC_HLS=0.
  • Token bootstrap admin sudah dihapus dari env.
  • Gateway diuji di sandbox: bayar, webhook diterima, akses terbuka, nominal cocok.
  • x402 diuji di Amoy dengan stablecoin dan token native.
  • Backup database terjadwal dan sudah pernah dipulihkan (restore test).
  • Rencana pemindahan dana rutin dari wallet admin x402 ke wallet dingin.
  • Kebijakan privasi, persetujuan pengguna, dan masa simpan data sudah ada (lihat bagian keamanan).
